## 1. 이름 겹치지 않게 관리하기

> **<font color="#c0504d">요약!</font>**<br>
> 나도 철수, 너도 철수... 어떻게 이름만 듣고 우리를 구별할까?

- 같은 이름의 함수나 변수는 동일한 동작을 해야한다. 

### http 라이브러리 예시
```jsx
// 이 서비스는 `http`라는 라이브러리를 쓰고 있어요
import { http as httpLibrary } from "@some-library/http";

export const http = {
  async get(url: string) {
    const token = await fetchToken();

    return httpLibrary.get(url, {
      headers: { Authorization: `Bearer ${token}` }
    });
  }
};
```

동작원리는 다음과 같다.
1. http라는 객체를 export한다.
2. get이라는 비동기 함수의 파라미터로 url문자열을 받음
3. fetchToken이라는 메서드를 이용해 token을 비동기로 가져옴
	1. await이므로, 토큰이 가져와지면 다음 코드 실행
4. httpLibrary의 get메서드로 url과 jwt를 이용해 요청을 보낸 값을 리턴받아 반환함.

뭐가 문제일까?

사용하는 http 라이브러리의 http와 get메서드가 해당 객체에서 사용되는 변수 혹은 함수명의 이름과 겹친다.

이렇게 되면, 나중에 에러가 생겼을때, 정확히 어떤 부분에서 문제인지 찾기위한 디버깅이 힘들어질 수 있다.

```jsx
// 이 서비스는 `http`라는 라이브러리를 씀
import { http as httpLibrary } from "@some-library/http";

// 라이브러리 함수명과 구분되도록 명칭을 변경
export const httpService = {
  async getWithAuth(url: string) {
    const token = await fetchToken();

    // 토큰을 헤더에 추가하는 등 인증 로직을 추가
    return httpLibrary.get(url, {
      headers: { Authorization: `Bearer ${token}` }
    });
  }
};
```

## 2. 같은 종류의 함수는 반환타입 통일하기

> **<font color="#c0504d">요약!</font>**<br>
> 같은 기능을 하는 함수나 hook은 반환타입 통일하기

- 같은 종류의 함수나 Hook은 서로다른 반환타입을 가지면 일관성이 헤쳐진다. 

### hook 예시

```jsx
import { useQuery } from '@tanstack/react-query';

function useUser() {
  const query = useQuery({
    queryKey: ['user'],
    queryFn: fetchUser
  });

  return query;
}

function useServerTime() {
  const query = useQuery({
    queryKey: ['serverTime'],
    queryFn: fetchServerTime
  });

  return query.data;
}
```

동작원리말고 각 코드가 무슨 역할인지만 살펴보자

1. 첫번째 코드는 useQuery를 이용해 query를 만들어, 반환한다.
2. 두번째 코드는 useQuery를 이용해 query를 만들어 .data를 반환한다.

문제는 딱 보인다.

같은 query를 반환하는 hook인데 하나는 query의 data를 반환하고, 하나는 query를 반환해서 거기서 data를 꺼내야 한다.

```jsx
import { useQuery } from '@tanstack/react-query';

function useUser() {
  const query = useQuery({
    queryKey: ['user'],
    queryFn: fetchUser
  });

  return query;
  //return query.data;
}

function useServerTime() {
  const query = useQuery({
    queryKey: ['serverTime'],
    queryFn: fetchServerTime
  });

  return query;
  //return query.data;
}
```

이렇게 query객체를 반환하거나, query.data를 동일하게 반환하도록 하면된다.

다만 query.data를 반환하게되면, query내부의 다른건 사용할수 없으므로, 충분한 팀 혹은 개인의 사유한 후 사용하면 된다.

### 일반 함수 예시

```jsx
/** 사용자 이름은 20자 미만이어야 해요. */
function checkIsNameValid(name: string) {
  const isValid = name.length > 0 && name.length < 20;

  return isValid;
}

/** 사용자 나이는 18세 이상 99세 이하의 자연수여야 해요. */
function checkIsAgeValid(age: number) {
  if (!Number.isInteger(age)) {
    return {
      ok: false,
      reason: "나이는 정수여야 해요."
    };
  }

  if (age < 18) {
    return {
      ok: false,
      reason: "나이는 18세 이상이어야 해요."
    };
  }

  if (age > 99) {
    return {
      ok: false,
      reason: "나이는 99세 이하이어야 해요."
    };
  }

  return { ok: true };
}
```

간단한 검증로직이다.

문제는 딱 보인다.

이름과 나이를 검증하는데, 

이름은 검증결과 리턴을 boolean값으로 하고있고,<br>
나이는 검증결과 리턴을 객체로 하고있다.
<br><br>
어떻게 해결할까?

반환값을 하나로 통일시켜주면 된다.

```jsx
/** 사용자 이름은 20자 미만이어야 해요. */
function checkIsNameValid(name: string) {
  if (name.length === 0) {
    return {
      ok: false,
      reason: "이름은 빈 값일 수 없어요."
    };
  } 
  
  if (name.length >= 20) {
    return {
      ok: false,
      reason: '이름은 20자 이상 입력할 수 없어요.'
    };
  }

  return { ok: true };
}

/** 사용자 나이는 18세 이상 99세 이하의 자연수여야 해요. */
function checkIsAgeValid(age: number) {
  if (!Number.isInteger(age)) {
    return {
      ok: false,
      reason: "나이는 정수여야 해요."
    };
  }

  if (age < 18) {
    return {
      ok: false,
      reason: "나이는 18세 이상이어야 해요."
    };
  }

  if (age > 99) {
    return {
      ok: false,
      reason: "나이는 99세 이하이어야 해요."
    };
  }

  return { ok: true };
}
```

추가적으로, 
반환타입도 하나의 타입으로 정의를 해두면 도움이 된다.


```jsx
type ValidationCheckReturnType = { ok: true } | { ok: false; reason: string };

function checkIsAgeValid(age: number): ValidationCheckReturnType {
  if (!Number.isInteger(age)) {
    return {
      ok: false,
      reason: "나이는 정수여야 해요."
    };
  }
  // ...
}

const isAgeValid = checkIsAgeValid(1.1);

if (isAgeValid.ok) {
  isAgeValid.reason; // 타입 에러: { ok: true } 타입에는 reason 속성이 없어요
} else {
  isAgeValid.reason; // ok가 false일 때만 reason 속성에 접근할 수 있어요
}
```


## 3. 숨은 로직 드러내기

> **<font color="#c0504d">요약!</font>**<br>
> 같은 기능을 하는 함수나 hook은 반환타입 통일하기

- 같은 종류의 함수나 Hook은 서로다른 반환타입을 가지면 일관성이 헤쳐진다. 

### 잔액 조회 예시

```jsx
async function fetchBalance(): Promise<number> {
  const balance = await http.get<number>("...");

  logging.log("balance_fetched");

  return balance;
}
```

문제점은 다음과 같다.

이 코드를 사용하는 모든곳에서 logging이 일어난다.
<br>
즉, 로깅이 필요하지 않은곳에서도 로깅이 일어난다.

또한 해당 로깅로직에 오류가 있을때, 해당 함수를 사용하는 모든곳이 망가진다.

그러니 다음처럼 로직만 구현부에 남기고
```jsx
async function fetchBalance(): Promise<number> {
  const balance = await http.get<number>("...");

  return balance;
}
```

```jsx
<Button
  onClick={async () => {
    const balance = await fetchBalance();
    logging.log("balance_fetched");

    await syncBalance(balance);
  }}
>
  계좌 잔액 갱신하기
</Button>
```

로깅하는 코드는 별도로 분리를 해주자.
